# StreamV2V full C++ port — implementation + testing plan

**Goal:** port the *complete* original StreamV2V algorithm (extended self-attention + feature
injection + ToMe bank merge) to the librediffusion C++/TRT-RTX engine, faithful to the canonical
Python reference. New CUDA kernels are allowed for the parts TRT can't bake. Validate meticulously
through 3 tiers: **original Python golden → new librediffusion-Python → C++ port**, then surface the
results in the HTML harness.

## 0. Orientation — read these first

### The canonical algorithm (Jeff-LiangF/streamv2v `src/streamv2v/models/attention_processor.py`)
`CachedSTAttnProcessor2_0.__call__`, per **self-attention** layer (attn1), per frame:
1. `q=to_q(h); k=to_k(h); v=to_v(h)`
2. **extended self-attention**: `k = cat([k, self.cached_key], 1); v = cat([v, self.cached_value], 1)`; then `SDPA(q, k, v)` — attends over current + banked K/V. **(the primary mechanism)**
3. `to_out`, residual, `/rescale_output_factor`
4. **feature injection**, ONLY for `up_blocks.0` / `up_blocks.1` / `mid_block`:
   `nn = get_nn_feats(h, self.cached_output, threshold); h = h*(1-fi) + fi*nn`
   - `get_nn_feats(x,y,thr)` (utils.py): `xn=normalize(x); yn=normalize(y); cos=xn@yn.T; idx=argmax(cos,-1); mask=max(cos)<thr; nn=gather(y,idx); out=where(mask, x, nn)` — per-token cosine-NN, keep-original-if-below-threshold.
5. **ToMe bank merge**, every `interval` frames: `_tome_step_kvout(k,v,out)` = `cat(bank, new)` then `random_bipartite_soft_matching(metric=keys, ratio=tome_ratio)` → compact bank. Bank stores **key, value, AND output**.

The fork's own `CachedSTAttnProcessorTRT2_0` (and daydream's processor) keep ONLY step 2 (kvo K/V concat); they drop 4 & 5 as un-TRT-able. **Our current C++ implements only a broken post-hoc version of step 4 and skips step 2 — it is unsalvageable and must be replaced.**

## ARCHITECTURE DECISION
- **Step 2 (extended attn)** → MUST bake into the engine (mid-graph SDPA over banked K/V). `kvo_cache_in/out`.
- **Step 4 (injection)** → BAKE into the engine (all ONNX ops) with `cached_output_in` for the 3 block groups; OR keep as a CUDA kernel only if you split the engine (messy — prefer baking).
- **Step 5 (ToMe)** → CUDA kernel + host bank manager (cross-frame, dynamic size — not bakeable).
- **Bank policy:** start with **simple rolling last-N** (cap `cache_maxframes`, static profile, ~90% of the benefit, no ToMe) → add ToMe only in the final phase.

#### Measured kvo engine I/O contract (for the C++ UNetWrapper rework — `unet.engine`, TRT-RTX 11)
36 io tensors. **19 inputs:**
- `sample` FLOAT `(-1,4,-1,-1)`  · `timestep` FLOAT `(-1,)`  · `encoder_hidden_states` HALF `(-1,77,768)`
- `kvo_cache_in_0..15` HALF `(2, -1, -1, seq, hidden)` — dims = `[2(K&V), cache_maxframes, B, seq, hidden]`;
  the maxframes (dim1) and B (dim2) are DYNAMIC. Per-layer (seq,hidden), in binding order 0..15:
  `(4096,320)×2, (1024,640)×2, (256,1280)×2, (64,1280)[mid], (256,1280)×3, (1024,640)×3, (4096,320)×3`
  = the 16 SD1.5 self-attn (attn1) layers in UNet traversal order (down0,down1,down2,mid,up1,up2,up3).

**17 outputs:** `latent` HALF `(-1,4,-1,-1)` + `kvo_cache_out_0..15` HALF `(2, 1, -1, -1, hidden)` =
this frame's new K/V, shape `[2, 1, B, seq, hidden]` (ONE frame slot; host rolls it into the bank).

Dynamic profile (profile 0): `sample` min`(1,4,32,32)` opt`(2,4,64,64)` max`(4,4,128,128)`;
`kvo_cache_in_0` min`(2,1,1,4096,320)` opt`(2,2,2,4096,320)` max`(2,4,4,4096,320)`. So engine supports
cache_maxframes ≤ 4 and batch ≤ 4. NOTE `sample` is FP32 in / `latent` is FP16 out (asymmetric).

C++ host loop per frame: bind 16 `kvo_cache_in_*` from the rolling bank `[2,maxframes,B,seq,h]`, enqueue,
read 16 `kvo_cache_out_*` `[2,1,B,seq,h]`, then roll bank `-1` on dim1 and write newest at `[:,−1]`
(mirror pipeline.py:911-922; cache_interval gating optional). Empty/zero bank on frame 0 == plain.
